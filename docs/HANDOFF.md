## 近期讨论浓缩：后续沿用的共识

1. 交付：2026-12-31前构建1个融合临床危险因素、临床特征、PET/MR双灌注图像特征的CMVD阴性/阳性模型，≥1例独立病例端到端演示。合成模拟不算真实模型或端到端验收。
2. 数据：医生诊断来自医院反馈，详细标准与逐病例诊断记录待补；暂无临床结构表，只设计候选字段，不为真实病例编值。用户称80例，本机79包，需对账并找回旧编号映射，不能按目录自动生成审核标签或重编号。
3. 产品与技术：用户选择本机桌面应用。PySide6+PyQtGraph界面，pydicom/NumPy读取，SimpleITK/SciPy处理，pandas/scikit-learn低维正则化Logistic融合基线；Torch/MONAI为后续可选。界面、读取、量化、模型分层。
4. 环境与目录：Python移出项目到E盘，代码/配置/依赖/合成样例分目录管理；不注册全局PATH。data原件只读，患者资料与输出不上传、不进Git，不暴露为前端静态目录。
5. 顺序：D1读取→D2桌面→D3 ROI/曲线→D4双灌注特征→D5队列→D6训练冻结→D7集成报告→D8独立交付。临床表、参考诊断/定量和独立病例从D0并行准备，cine自动分割不是首版前置条件。
6. 验证：患者级划分，当前两例已用于开发，不能用于最终独立测试；特征/阈值/模型冻结后再用独立病例。每阶段记录实际覆盖、失败与证据，不把工程检查当临床效能。
