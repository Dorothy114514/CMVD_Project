## 2. 初步调研与技术判断

1. [2024 ESC慢性冠脉综合征指南](https://www.escardio.org/guidelines/clinical-practice-guidelines/all-esc-practice-guidelines/chronic-coronary-syndromes)及其[核心信息](https://www.escardio.org/static-file/Escardio/Guidelines/Products/Essential%20Messages/2024%20EM/Essential%20Messages_2024%20CCS.pdf)强调ANOCA/INOCA评估，PET用于绝对MBF测量，CMR灌注可作另一种评估途径。推论：需要核实阻塞性病变排除、实际检查协议及CMVD参考标准，不能将现有目录标签当作临床确诊。
2. [SNMMI/ASNC PET心肌血流定量立场文件](https://jnm.snmjournals.org/content/59/2/273)是PET定量方法的参考（2018，DOI `10.2967/jnumed.117.201368`）；本次官网全文访问403，未据此采用具体诊断阈值或动力学参数。PET接入优先核实经质控的工作站MBF/MFR导出，其次再考虑自行实现动力学定量。
3. [TRIPOD+AI官方扩展清单](https://www.tripod-statement.org/wp-content/uploads/2024/04/TRIPODAI-Supplement.pdf)要求交代结局标准、预测变量、缺失处理、样本数、患者级无泄漏划分、模型与阈值、性能及复现条件。推论：先冻结标签和划分，再进行训练；所有需要拟合的预处理仅在训练折内进行。

**工程选择（待真实数据验证）**：约80例优先建立低维、正则化Logistic特征融合基线。先获得可信双灌注特征，再比较更复杂模型；不能因图像切片多而把患者样本量视为足够训练大型3D网络。没有依据承诺准确率、AUC或临床效能。

## 3. 流程与模块边界

```mermaid
flowchart LR
  A[临床危险因素] --> E[字段与单位检查]
  B[临床特征] --> E
  P[本地PET静息/负荷影像] --> Q[PET质控与定量适配器]
  M[本地MR静息/负荷灌注影像] --> R[MR质控与特征适配器]
  Q --> E
  R --> E
  E --> S{三类输入和双灌注均可用}
  S -->|通过| F[训练折内预处理与特征融合]
  S -->|不通过| X[停止诊断并列出原因]
  F --> G[冻结模型推理]
  G --> H[阳性概率与阴性/阳性结果]
  H --> I[本地结果报告与追溯记录]
```

| 模块 | 输入 → 输出 | 交付要求 |
|---|---|---|
| 病例索引 | 既有研究编号 → 单患者资料关联 | 复用`metadata/full_case_manifest.csv`；先查表头，不复制第二份病例索引；重复检查同患者保持同一分组 |
| 临床适配器 | 受控临床表 → 危险因素/临床特征 | 明确单位、采集时点、缺失原因；姓名和目录标签不作特征 |
| PET适配器 | 静息/负荷动态影像或本地工作站输出 → MBF、MFR与QC | 记录方法/版本/来源；核实时间帧、活度单位、衰变/衰减校正、输入函数和运动；单纯SUV不能替代MBF |
| MR适配器 | 静息/负荷首过灌注 → 可追溯灌注特征与QC | 核实实际协议；先实现运动校正、ROI与信号时间曲线。归一化上升斜率比为半定量MPRI，不宣称是绝对MBF或定量MPR |
| 辅助影像 | cine、LGE、T1/T2 → 可选补充特征 | LVEF、EDV/ESV可辅助，不替代MR灌注；手工ROI先支撑闭环，自动分割后续接入 |
| 融合训练 | 审核标签、患者划分与特征 → 模型包 | 特征白名单、训练折内拟合、锁定阈值；记录依赖、随机种子与输入版本 |
| 本地演示入口 | 单例输入 → QC、概率、二分类与报告 | 缺少PET或MR灌注时拒绝诊断；真实推理使用冻结模型；不向前端公开数据路径或提供静态数据目录 |

第一阶段可以使用经过审核的工作站/人工ROI特征接入来完成**特征输入到输出**的闭环。最终从重建影像开始的演示仍需补齐并验证影像适配器；不能把手工填写灌注数字称作已完成自动影像端到端系统。

## 4. 数据合同与标签

机器可读合同见 [configs/demo_contract.json](../configs/demo_contract.json)。候选字段是工程接口草案，临床确认后版本化；当前配置供合成输入校验，不是最终CRF或临床阈值。没有新增真实病例清单。

- 危险因素：年龄、高血压、糖尿病、吸烟；性别、BMI、月经史等保留为待讨论候选。
- 临床特征：静息心率、LDL-C作为接口示例；血常规、空腹血糖、NT-proBNP、症状等待确认后扩展。
- PET：静息/负荷MBF，单位`mL/min/g`；MFR为负荷/静息比值，无量纲。
- MR：静息/负荷**归一化**信号上升斜率，统一单位`s^-1`，必须由同一规范的方法产生；MPRI为其比值，无量纲。以后若接入绝对定量需另开合同版本，不混用两种含义。
- 每个灌注分支附`method`、`source_reference`、`qc_status`、`reviewed_by`；实际存储的是本地研究引用和审核者代码，真实身份映射另行受控。
- 病例ID仅关联资料，绝不作为训练特征；POS/NEG前缀不作为诊断输入或标签推导规则。

用户于2026-10-19确认：病例标签来自医院反馈的医生诊断，尚无临床结构表，允许先假设常见参考字段。标签来源已明确，具体诊断标准与逐病例记录仍待提供；后续补齐标准版本、阴性定义、阻塞性病变/痉挛排除依据、判定日期与审核者、分歧处理、预测变量可用时点。标签单独存放于受控位置，不能混进单例推理输入。

候选字典见`configs/clinical_candidate_fields.json`：7个危险因素候选、17个临床特征候选及BMI/PLR两项派生候选。它扩展采集设计，不改变当前合成模型的8项融合特征。`examples/templates/clinical_features.csv`与`diagnosis_labels.csv`仅含表头，无真实病例；标签约定0=医生诊断阴性、1=医生诊断阳性、空值=待定，`label_source`填`hospital_reported_physician_diagnosis`并记录来源引用；不得由POS/NEG前缀自动产生。真实表后续存放于受控`metadata/`，不另复制既有病例索引。

特别检查**循环定义偏倚**：若阳性完全由PET MFR阈值定义，而输入同时包括该MFR，模型可能只学到阈值复刻。应说明参考标准与输入指标的关系，设计相应敏感性/消融分析，不能把这种一致性称为独立诊断能力。

1. 对账80例与历史79例：确认新增病例、重复就诊和既有编号，不重新排序编号；继承POS-008、NEG-018等既有数据问题。先按临床表和模态可用性统计纳入/排除，不扫描重处理全部像素。
2. 用户2026-10-20确认能另补40例独立验证，采用现有约80例开发＋新增40例独立测试的规划（第17节）。80例可内部交叉验证并在方案锁定后全开发集重训；40例不参与选择、调参或阈值。新增资料尚未收到，79/80与患者数仍需核对；同院新增病例属于独立/时间验证，不自动称跨中心外部验证。
3. 用研究患者ID冻结开发/测试划分；同患者所有模态、切片、时相、重访进入同一集合。测试病例不用于选特征、填补、调参、阈值或人工修改规则。
4. 在开发集作患者级分层交叉验证；折数依据最终较少类别人数确定，必要时减少。首个基线固定L2 Logistic与少量预先指定特征；不在全数据先筛特征。若搜索正则强度/变量/阈值，使用内层交叉验证，外层评估；标准化、填补、特征筛选均在折内拟合。
5. 首版合成骨架对任何缺失值拒绝推理。真实模型再明确预先规定的缺失上限、开发折内填补和缺失指示；整个PET或MR灌注分支缺失，不通过填零伪装为三类融合。
6. 报告患者数、阳性数、缺失与排除；开发集OOF AUC、敏感度、特异度、平衡准确率、混淆矩阵及Brier，按可行性提供患者级不确定性估计；消融比较临床、临床+PET、临床+MR、全融合。先锁定方案，避免小样本反复挑选最优结果。
7. ≥1例测试仅承担功能演示：可展示单例预测与参考结果，不能据单例计算有效AUC或声称泛化/临床验证。若测试集单类别，AUC标记不可计算。最终阈值由开发数据和临床目标预先确定，不能看测试结果调到“演示正确”。

模型包应包含：模型与预处理、合同版本、特征顺序与单位、标签标准、阈值及依据、患者划分引用/摘要、训练数据版本、随机种子、依赖版本、代码版本、评估报告及限制。禁止以不可信pickle文件作为外来模型直接加载。

## 9. 根据两例实际样本收敛技术栈

### 样本事实及其设计约束

入口是已重建、未去标识/未分析的临床DICOM影像；本次两个样例均为`.IMA`文件，不是PET list-mode或MR k-space输入。顶层仅计数到31个阳性7z、48个阴性7z，各有一个解压样例；未打开压缩包。两例分别8,126/8,151个对象、45/50个SeriesInstanceUID；其中PT各7,112个，MR分别1,010/1,034个，其余为NM/OT Secondary Capture。本次2例16,277个头字段读取/汇总完成，不能外推为79/80例已核验。

| 实际结构（两例均观察到） | 工程决策 |
|---|---|
| PET静息和负荷各127层、172×172、19个动态时间帧；各动态序列2,413个空间-时间单元齐备、无重复对象 | 按位置/方向与时间联合组装`[t,z,y,x]`；静态、门控、动态分别入型，不能混装 |
| PET另有静态127张和8门控×127层；像素单位BQML、DecayCorrection=START、半衰期597.9s、注射剂量/起始时间字段存在 | 保留原始定量及时间元数据；参数存在不等于动力学定量已正确或已取得MBF |
| PET19帧时长为12×10s、2×30s、4×60s、1×180s，总600s；参考时间不总等于简单帧中点 | 时间使用实际DICOM字段，明确参考时刻和衰变约定，再处理输入函数/拟合；不按等间隔19帧计算 |
| MR静息/负荷各4组单平面×70张；方向与cine比较支持3个短轴候选平面+1个长轴候选平面 | 每个平面独立保留`[t,y,x]`和几何，短轴层级需人工确认；不伪造为连续3D灌注体积 |
| MR灌注70个实际采集时点，时间间隔随病例和静息/负荷变化；观察范围约0.635–3.395s/步 | 斜率、TTP和配准使用真实时间轴；显示帧数与物理时间分开 |
| cine短轴10层，每层独立Series、25时相、208×174；层厚8mm、层中心距10mm；各层触发时间网格并不完全一致 | 跨Series组装，保存逐层触发时间；基于周期信息规范化相位并人工核验，不能用层厚直接代替层距 |
| 样本另有T1/T2、PSIR等序列；存在有效的Secondary Capture对象且SeriesNumber可为空 | 序列索引按UID和实际几何/内容；SeriesNumber只作辅助。截图/报告单独归类，不进入原生MR/PT像素通道 |

PET单个动态序列按float32装载约272 MiB，静息+负荷仅动态部分约545 MiB。因此采用按需解码、逐序列处理和受控磁盘缓存，不把全部病例和模态一次加载到内存。检查器只输出技术字段和少量原生像素预览；原始身份字段、自由文本和UID不写入摘要。预览仍是受控研究派生物，未完成像素隐私检查或临床诊断。

空间与时间处理依据[DICOM图像平面定义](https://dicom.nema.org/medical/dicom/current/output/chtml/part03/sect_C.7.6.2.html)和[PET Image Module](https://dicom.nema.org/medical/dicom/current/output/chtml/part03/sect_C.8.9.4.html)：层厚与空间位置不是同一概念，FrameReferenceTime含义也不能简单等同任意序列的帧中点。

### 模块及数据对象

采用单机分层模块，桌面通过后台worker调用应用服务；计算任务提供进度/取消，工作线程不直接修改界面。无需为首版引入独立Web服务或数据库运维；病例关联复用既有清单，受控特征表提供新增研究信息。

```mermaid
flowchart LR
  UI[PySide6桌面与PyQtGraph显示] --> S[应用服务与后台任务]
  S --> IO[DICOM索引和空间时间组装]
  IO --> QC[分支质控和人工ROI]
  QC --> PET[PET曲线与定量适配器]
  QC --> MR[MR逐平面信号特征]
  C[受控临床表] --> F[三类输入FeatureBundle]
  PET --> F
  MR --> F
  F --> ML[训练或冻结模型推理]
  ML --> R[本地研究报告]
```

后续按实际实现扩展`src/cmvd_demo/`的`io`、`processing`、`features`、`modeling`、`ui`和`reporting`模块，暂不创建空目录。核心数据对象不得依赖Qt：

- `PetDynamicVolume`：`data[t,z,y,x]`、LPS几何、逐帧参考时间/时长、单位及定量元数据。
- `CineStack`：`data[z,phase,y,x]`、逐层位置/方向和触发时间；周期相位映射、缺层和覆盖QC独立保存。
- `MrPerfusionPlane`：`data[t,y,x]`、平面位置/方向、真实相对采集时间、静息/负荷和待审核的平面角色。
- `FeatureBundle`：三类输入、单位、来源、方法版本和QC；患者关联键不进入模型特征。

内部图像缓存可先用`.npy`/memmap与JSON侧车，侧车保留时间和物理坐标；NIfTI用于需要时与3D Slicer交换，转换不能丢弃时间/单位信息。显示通道与定量通道分开，原始DICOM只读。

### 先实现的闭环及研究待定项

第一步交付真实样例的桌面浏览：序列树、PET静息/负荷动态切片、MR逐平面灌注播放、cine跨层/时相、可修正ROI和原始曲线；从这里核验几何和时间轴，再接入临床表和真实融合模型。先在每例明确三类输入可用性与QC，失败时不输出诊断。

PET MBF/MFR优先接审核过的工作站结果，并与本地TAC/元数据核对；自主动力学需要输入函数、时间/衰变、运动及模型标定验证。MR逐平面分析先用手工逐帧ROI修正、原始曲线与上升斜率/峰值/TTP；自动配准另设验证前提，不能把手工修正称为已完成自动运动校正。半定量储备指标需先统一剂量/归一化与采集规则，不能称为已实现绝对MBF。两条研究路径不能仅凭DICOM头存在而视为验证完成。

UI采用本机Qt工作站；读取、ROI/量化、队列与模型分层，具体接口见11–17节。资料未齐时可独立推进基础功能与合成训练链；真实训练要求病例关联、医生标签、临床表及D4测量审核通过。80开发＋另补40独立的安排见17节，不能由79个压缩包直接认定已有80位合格患者；实际进度及验证只查HANDOFF。

| 接口 | 输入与输出 |
|---|---|
| `scan_case(case_dir, progress=None, cancel=None)` | 显式单病例目录；按Study/Series UID分组，返回Series与逐文件Issue；压缩包不打开，目录前缀不推导诊断标签 |
| `build_grid(series)` | 原生单帧PET动态/静态/门控、MR逐平面灌注/cine；校验后返回懒加载ImageGrid，异常不补零 |
| `build_cine_stack(series_list)` | 显式选中的同Study/FrameOfReference短轴cine Series；按物理层位合并，保留每层触发时间，不宣称相位同步 |
| `grid.read_plane(t, z)` / `grid.materialize(...)` | 按需解码/单网格加载float32定量值；后者默认单数组512 MiB预算，支持进度/取消 |
| `read_pixels(header, scaled=True)` | 单对象像素；逐对象应用slope/intercept，PET要求单位与缩放，MONOCHROME1反相交给显示层 |

数组轴为`[时间或相位序号, 层面, 行, 列]`；`times_s`和动态PET帧长为`[层面, 时间]`。MR灌注使用真实非等间隔采集时间并减去本Series首时点；不同平面时间零点不能据此当作同一绝对起点。PET保留FrameReferenceTime和ActualFrameDuration，不能把衰变相关参考时刻简单替换为帧中点。cine的触发时间直接保留，跨层相位序号不是同步结果。

坐标使用DICOM LPS：`origin[z] + IOP[:3] * column * PixelSpacing[1] + IOP[3:] * row * PixelSpacing[0]`；提供`pixel_to_lps`/`lps_to_pixel`。层中心距独立于SliceThickness，不以文件名或InstanceNumber排序。依据见[DICOM Image Plane](https://dicom.nema.org/medical/dicom/current/output/chtml/part03/sect_C.7.6.2.html)、[PET Image Module](https://dicom.nema.org/medical/dicom/current/output/chtml/part03/sect_C.8.9.4.html)及[pydicom像素解码说明](https://pydicom.github.io/pydicom/stable/tutorials/pixel_data/introduction.html)。

`progress(stage, done, total)`只传计数；`cancel()`为真时抛出`ReadCancelled`，不返回部分成功对象。桌面线程还需按任务版本丢弃过期结果。物化预算约束单个输出数组，不保证进程总内存低于512 MiB；D2优先按需读取并限制缓存。原路径/UID/绝对日期仅保留内存对象中，`safe_summary()`不输出这些字段；摘要依然按研究资料受控保存。

缺失时间、重复对象/单元、不一致几何或定量单位、已声明但缺失的层/帧、读取后源文件变化均显式报错。若整层/整帧缺失且无数量/间距等证据，单凭剩余头字段无法证明缺失。截图、Enhanced/多帧及其他SOP可索引但拒绝主线组装；其他MR尚不提供通用体积组装，压缩传输语法也未验收。分类使用头字段与协议词候选，需要人工确认静息/负荷和序列用途，不代表临床审核。

回归脚本`validate_reader.py --samples`只针对当前两例开发样本执行结构断言与主线像素解码，逐网格释放数组；失败写入报告并返回非零退出码，不覆盖既有报告。它不是全队列审计或独立测试，人工方向对照、像素隐私和临床定量分别验收。

## 12. D2桌面浏览

主界面工具栏用于打开病例目录与取消任务；方向/播放/ROI体模仅从“合成演示→影像浏览与轮廓练习（完全合成）”进入，D4首过灌注演示也在该菜单。默认空工作区提示打开病例；保留`--synthetic`供明确指定的工程演示启动。

入口`scripts/desktop/start.ps1`通过统一解释器启动`run_desktop.py`，默认空工作区；`--synthetic`为完全虚构的方向/时间体模，`--case-dir`为显式单病例目录。无网络服务、自动解压、持久病例索引或诊断调用。桌面源码在`src/cmvd_demo/desktop/`，与D1读取及合成推理分开。

- 序列树按静息/负荷候选分组，显示安全序列号与用途，不显示姓名、原路径或UID；不可显示对象置灰保留计数。MR灌注保持逐平面Series；同Study/FrameOfReference/方向的短轴cine生成组合候选，由用户选择后调用D1再次校验，不把所有cine自动合并。
- 所有DICOM索引、组装和像素读取在后台执行；前台请求通道为一个运行任务加一个可替换的最新待执行任务，带取消标记和请求版本。切换病例/序列、滑块请求和取消都会失效旧任务；只有当前版本可更新图像或缓存。另有一个可取消预读通道，不阻塞前台单帧请求；关闭窗口先隐藏，两个通道的在读操作返回后退出，不能强行中断正在进行的单次系统I/O。
- 只按需读取单帧，64 MiB LRU缓存；单帧float32输出上限16 MiB，在解码前检查。展示新帧后最多预读后续4帧（静态序列预读相邻层），大帧自动减少预读数；共用现有缓存预算，过期预读不入缓存。缓存命中仍在后台核对源文件size/mtime；换病例/关闭清空缓存。限制不等于进程总内存保证，后台临时批次/解码另占内存，未建立整幅4D磁盘缓存。
- 图像按row-major、上到下行序显示；通过行/列PixelSpacing保持物理比例。像素中心与DICOM坐标一致（首像素中心位于图像本地0.5/0.5，显示矩形起点为负半间距），鼠标可查看原始定量值和LPS坐标。方向标注基于IOP的主要/次要LPS分量；保留原始采集平面，不自动重排成标准轴位。独立查看器方向核对未完成时，D3结果仅作为未审核预览。
- 窗宽/窗位、百分位自动窗、MONOCHROME1显示LUT不改变定量数组；手动窗位与缩放在逐帧切换时保留。几何变换与灰阶LUT不在每帧重复构建。PET显示参考时间/帧长，MR显示真实相对时间，cine显示当前层触发时间并提示未同步。
- 同网格切帧保留上一幅有效影像、指针与实际时间/层面标签，状态栏另示目标；新帧完成读取后整体替换。连续拖动按45 ms限频合并请求，松手立即加载最终位置，不因持续重启防抖而一直无预览。换病例/序列、主动取消或读取失败仍清空图像。
- 播放使用单次定时器：`PresentedImageItem.paint()`调用基类绘制后确认本帧，再等待设定间隔并请求下一帧；不以`sigImageChanged`当作已绘制，不在定时器上无条件跳帧。默认15 fps，可设1–30；读取或绘制慢时降低实际速度，快拖主动暂停播放。此确认仅代表Qt绘制完成，不保证显示器扫描输出、垂直同步或其他机器帧率；浏览速度不模拟采集速度。
- 失败/取消清除影像，不输出阴性或阳性；双击序列/回车可重试。无模型显示“模型未配置”，不提供诊断按钮；D3的ROI/曲线工作区见第13节。

Qt后台模型参考[Qt QThreadPool文档](https://doc.qt.io/qtforpython-6.10/PySide6/QtCore/QThreadPool.html)，显示轴/矩形变换参考[PyQtGraph ImageItem文档](https://pyqtgraph.readthedocs.io/en/pyqtgraph-0.14.0/api_reference/graphicsItems/imageitem.html)。版本固定于requirements，执行状态只记HANDOFF。

`tests/test_desktop.py`用已知不对称体模验证方向、像素中心、非等间距比例、原值/显示分离、非均匀时间、缓存、后台响应、取消/过期消息、重试和关闭/重开。`check_desktop.py --samples`在原生Qt窗口按主线序列检查真实首末帧，与源对象独立解码/缩放算术核对；只保存合成截图。自动等待用QEventLoop让后台I/O持续运行；QTest仅用于具体控件动作，避免紧密qWait轮询拖慢后台枚举。自动交互不替代T2独立查看器比较、T3人工验收或临床验证。

`--samples --navigation`另检查每例PET动态、MR灌注、cine各一组：连续8帧的Qt绘制顺序/间隔、等待期间空白观察、51次快速目标变更与松手后的最终源像素匹配。软件测试用延迟读取和禁止viewport更新验证未绘制帧不会推进，并检查保留原帧/标签、预读缓存及旧病例清理。帧率只报告测量结果，不作为未经验证的全队列速度承诺。

## 13. D3人工ROI与原始曲线

领域层位于`src/cmvd_demo/roi/`，不依赖Qt；桌面`RoiPanel`复用D1单帧读取，使用独立可取消任务计算曲线/读写快照。只计算当前选中层面，不将不同MR平面时间零点或cine层间相位强行同步。初始几何轮廓不是自动分割或解剖标注；真实方向/覆盖、轮廓与运动仍需人核对。

| 对象/接口 | 约定 |
|---|---|
| `new_document(grid)` | schema v1、用途、来源绑定、ROI轨迹与两个默认false的本地复核项 |
| `binding_for(grid)` | DICOM技术身份/size-mtime/定量头字段的SHA-256签名，另保留形状、LPS几何、单位、逐层时间/帧长；不保存原路径、姓名、原始UID或绝对日期 |
| `set_track(...,frame_only=False)` | 每层最多心肌/血池各一条轨迹；参考帧/轮廓与显式逐帧覆盖。参考改动影响未单独修正帧，既有逐帧覆盖保留 |
| `contour_mask(contour,shape)` | 顶点为`[row,column]`，整数代表像素中心；外多边形可含内膜排除，按像素中心选取，外边界包含、内边界排除 |
| `extract_curves(grid,doc,z,...)` | 当前层完整时序，输出均值/总体标准差/最小最大、像素数/面积、真实时间/帧长/单位、方法版本和QC；失败不返回部分成功曲线 |
| `save_snapshot(root,doc,result)` / `load_document(path,binding)` | 不覆盖的独立新快照；重载时严格核对当前来源/几何/时间；旧ROI版本与新曲线版本不一致拒绝导出 |

坐标转换：编辑器轮廓挂在ImageItem之下，本地`(x,y)=(column+0.5,row+0.5)`；保存时减去半像素并交换为RC。实际LPS沿用D1的IOP/PixelSpacing/origin，不用截图坐标取样。物理面积为有效像素数×行间距×列间距；统计使用D1定量float32像素、float64累计，与窗宽/窗位、MONOCHROME1显示LUT无关。数据不做时间平滑、插值、信号归一化或图像重采样；PET BQML均值不是MBF或SUV，MR输出是原始信号强度。

运动处理采用**固定参考轮廓加逐帧手工覆盖**，覆盖之间不插值，也不跨层/跨序列传播。可在某帧调整心肌内外边界与血池；需复核的帧逐帧修改，未修改帧明确沿用参考。暂不提供未经审核的自动配准/自动分割。软件测试以已知平移的亮块验证手工修正后的曲线；不能据此声称真实心肌运动已验证。

轮廓要求有限、在图像边界内、不自交、有有效像素；内轮廓必须严格位于外轮廓内。计算时心肌/血池不能重叠。单轮廓最多128顶点，文档最多1024轨迹；逐帧掩膜缓存限制16 MiB，原始图像按帧读取，不加载整幅4D。固定/已接受轮廓采用常驻Qt编辑对象复用，切换隐藏再更新，避免在频繁重建PolyLineROI子图时出现原生对象生命周期问题。

鼠标工具分为“编辑轮廓点”“移动整个轮廓”“平移影像”。放置或重载ROI自动进入控制点工具：控制点屏幕半径8 px，只显示当前可编辑角色的控制点；左键未命中时由ViewBox消费，不平移背景或整体轮廓，也不通过Alt/Shift对轮廓旋转/缩放。整体移动工具只启用当前角色的轮廓平移并隐藏控制点，边线拖动转发给对应父ROI，心肌内外边界等量联动并共同计为一步；平移图像工具锁定所有ROI。中键平移、滚轮缩放仍可用。继承已固定PyQtGraph 0.14的Handle/线段实现，显式排除禁用轮廓参与hover/drag，避免自定义GraphicsScene绕过Qt禁用状态或线段吞掉拖动。

`roi/history.py`提供无Qt的几何历史：每次有效操作记录修改前后tracks及帧/层/角色/参考或本帧模式，不保存复核状态或旧曲线；按序列隔离，整个当前病例合计最多50操作/16 MiB序列化内容，超限裁剪旧历史，单步超限清空该序列历史以免跨过未记录修改。一次拖动直到松手才提交一步，增删顶点屏蔽库内部中间信号后原子提交。支持放置/删除、内膜开关、逐帧覆盖/重置、重载；空操作不入栈，新编辑清除本序列redo。撤销/重做恢复目标编辑帧和角色，保留来源绑定，全部本地复核置false并取消过期任务/清除曲线；失效D4特征不因撤销而恢复。无效编辑不进历史，可按撤销回最后有效轮廓。病例切换/关闭不保留历史；同病例切回序列可继续，来源绑定变化则清该序列历史。文本输入控件保留其原生文本撤销，ROI快捷键为Ctrl+Z/Ctrl+Y/Ctrl+Shift+Z。

ROI修改立即使旧曲线和两个本地复核项失效；快拖保留上一帧时，ROI也保留对应旧帧，目标尚未接受时禁用编辑。开始拖动ROI会停止播放并取消未接受切帧，防止把轮廓写到错误时间帧。换层只显示该层轮廓；同病例切换序列可在内存中恢复各自ROI，换病例清空未保存内容，界面提醒先保存。曲线任务以病例/序列/文档版本/层面校验返回值，过期结果不发布。取消/读取失败清除相应曲线，不输出阴性/阳性。

快照在受控`outputs/roi/<UTC时间戳-随机ID>/`：`roi.json`为规范JSON（4 MiB上限，过大在写出前拒绝），全序列已标注ROI及其来源；存在当前有效曲线才同时写`curves.json`和`curves.csv`，只导出当前计算层。全部写出后才创建`bundle.json`并标记completed；失败残留目录没有完成标记，应保留定位，不覆盖/续写。时间戳为软件操作时间；来源签名不是逐文件像素哈希，不能当作数据防篡改或匿名化证明。

QC始终`clinical_validated=false`；`feature_input_ready`要求有效双ROI、本地两项复核、动态灌注分支及合适单位，不代表医院/参考工作站验证。`engineering_fixture`用途即使勾选复核也不能成为已审核特征输入；cine曲线明确非灌注分支。D4特征合同见下一节，诊断与真实定量参考验证仍待完成。

验证包括已知矩形/环形真值、非均匀时间、float64统计、逐帧运动修正、原生PET缩放/帧长、非法几何/重叠/取消、源绑定错配、CSV/JSON复算、导出失败及Qt对象复用。`check_desktop.py --samples --roi --navigation`用独立Qt多边形取样与源DICOM解码/缩放核对工程均值、面积、时间、覆盖和保存/重载；测试轮廓明确是engineering_fixture。只截图合成体模，真实ROI/曲线同样按研究资料受控，不作为临床效能、像素隐私检查或人工方向验收证据。编辑API参见[PyQtGraph ROI文档](https://pyqtgraph.readthedocs.io/en/pyqtgraph-0.14.0/api_reference/graphicsItems/roi.html)。

### 13.1 图上勾画与边界隔离

`roi.placement`提供无Qt的手工放置几何，`desktop.roi_drawing.RoiDrawing`接收`RoiViewBox`的原生场景事件，复用当前ImageItem到RC的半像素变换。椭圆由用户拖出的包围范围生成16个顶点，行列方向均至少2像素；逐点模式最多128点，Enter/双击/回首点完成，Backspace或Ctrl+Z撤一点，Esc/右键取消。预览为挂在ImageItem下常驻的PlotDataItem，隐藏/更新而非反复创建编辑图形；单个首点也可见。中键平移和滚轮缩放仍可使用，左键草稿事件不落到原ROI或背景平移。

勾画开始时绑定病例版本、安全序列key、显示帧/层面、角色、参考/单帧范围、边界选择和原ROI文档摘要。未完成草稿不修改文档、曲线、审核或历史；校验失败留红色草稿可撤点/取消。有效完成后走原`set_track`/`_replace_document`，整次勾画一次历史，按原规则使旧曲线、复核及保留特征失效。只有完成轮廓可保存；勾画中禁止分析/保存，工作恢复要求先完成或取消草稿。切帧/层面、角色、范围、工具、病例/序列、关闭分析面板或离开轮廓页会取消草稿，发布前再比较上下文，防止旧坐标写到新帧。

心肌“内外膜一起编辑／只编辑心外膜／只编辑心内膜”控制顶点和线段编辑权限，锁定边界不参与命中/拖动。单独重画外膜保留已有内膜，重画内膜要求已有外膜；新的内外膜组合必须通过原严格包含、无交叉、有效像素等检查。一起新建时可按外轮廓缩小0.55生成内膜手工起点，界面明确要求核对；不读取像素推断边界，不称自动分割。血池仅有外轮廓。整体移动工具仍同时移动心肌内外膜，避免破坏原“移动整个轮廓”的语义。参考模式不能覆盖当前帧的既有独立轮廓；单帧重画必须先有参考，其余帧不受影响，也不插值。

PyQtGraph默认控制点菜单及曲线菜单是无QWidget父对象的原生窗口，Python后台GC可能在绘制期间析构残留菜单并互锁。控制点/ROI菜单显式归属工作站窗口，曲线菜单归属PlotWidget，设置父对象时保留原Popup等windowFlags；移除的控制点、线段及其菜单在GUI线程deleteLater，关闭仍先等待后台通道再DeferredDelete。验证应检查原生对象销毁、菜单非自动可见、后台GC与反复增删点，不能用禁用GC替代。

ROI schema、来源绑定、掩膜统计及原工作记录合同不变；草稿、边界编辑筛选器及其临时快捷键不持久化。恢复仍按已保存有效ROI复算，不能恢复未完成草稿。真实解剖位置、内外膜排除、全时序运动和定量有效性仍需原人工审核，不因新的交互或自动测试通过而升级。

## 14. D4探索性双灌注特征与工作站适配

`src/cmvd_demo/perfusion/`是无Qt特征层，桌面`FeaturePanel`通过可取消后台任务调用；不接入旧的固定合成系数或真实诊断。此层仅输出灌注FeatureBundle，尚无临床字段/标签和训练矩阵。真实PET工作站结果、MR参考、解剖标注及T2/T3/T4人工核对缺失时保持未验收，不影响工程预览。

### 14.1 MR逐平面计算合同

方法ID `mr_baseline_subtracted_adjacent_upslope_v1`，仅接受D3同版本双ROI曲线及`mr_perfusion`分支。MR信号单位必须为`MR_SIGNAL_AU`或显式合成单位；cine、PET、缺失/不递增时间、错配ROI文档或单位拒绝使用。

参数为0起始的`baseline_start`、至少2帧的`baseline_frames`、含首尾的`window_start/window_end`，基线区间必须在分析窗口前。界面所有帧号从1计，API/JSON从0计；基线均值为所选连续帧信号平均。允许人工避开初始信号过渡，不自动检测注射时刻或挑窗。参考和训练规则冻结前必须确认真实基线/首过区间，不能把首帧默认当可靠基线。

每个ROI输出基线、窗口内最早峰值、峰值减基线、相对增强`(peak-baseline)/baseline`、采集相对峰值时间、`peak_time-time[window_start-1]`、最大相邻采样上升斜率与带符号增强AUC。上升斜率在`window_start-1`至峰值之间按`ΔSI/Δt`取最大值；AUC在`window_start-1`至`window_end`对基线减除信号用真实非等间隔时间作梯形积分，不裁剪负面积、不平滑/插值/重采样。TTP是相对分析窗口起点，**不是注射后达峰时间**；单个采样间隔斜率对噪声敏感，不能视为经过临床验证的拟合估计。

归一化上升斜率为心肌原始信号斜率/血池原始信号斜率，单位`1`；不作各自基线除法或剂量校正。每个ROI基线、上升斜率及峰值增强须为正，否则拒绝本次派生；峰值在分析窗口边界则输出警告。此约定是明确版本的探索性算法。与[SCMR 2020后处理建议](https://events.scmr.org/wp-content/uploads/2024/08/Post-processing.pdf)中使用信号时间曲线、峰值/达峰时间及可由血池斜率归一化的思路一致，但不能声称该建议验证了本工程的相邻差分、窗口选择或容差。

`pair_mr`只配对同病例上下文、同方法/协议代码/信号单位、不同来源签名、方向余弦近似一致的静息/负荷平面。MPRI=负荷归一化斜率/静息归一化斜率。方向筛查不证明同一解剖位置，必须另记状态/解剖平面及剂量/序列/协议可比较性的人工复核；不按序列号、层序或目录自动配对，不跨平面平均。旧`configs/demo_contract.json`中的`s^-1`是早期独立合成接口，不是本方法的量纲；D4不自动映射到该接口或既有演示系数。

### 14.2 PET工作站适配

先保留本病例静息/负荷动态PET双ROI曲线，然后导出空`pet_request.json`供本地受控填写。`schema_version=1`、`kind=pet_workstation_result`；字段严格匹配，包括临时`case_token`、`unit=mL/min/g`、`region=global_lv`、`method_id/software_version/protocol_id/tracer/reference_id/reviewer_code/qc_passed`、可空`reported_mfr`、`mfr_absolute_tolerance`以及`branches.rest/stress`。每个分支有正数`mbf`与`binding`（源签名、ROI文档哈希、曲线哈希、层面）；未知字段、空/REPLACE来源代码、错误单位/范围/状态、同源配对及任何错配拒绝导入。

结果为外部全左室静息/负荷MBF及其比值MFR；如提供工作站MFR，按事先指定绝对容差核对，默认0.01、工程允许0–0.1，不是临床阈值。[SNMMI/ASNC立场文件](https://jnm.snmjournals.org/content/59/2/273)支持MBF单位和stress/rest MFR定义；本层不重建其动力学方法。当前单层本地TAC仅核对来源、时间/帧长、单位BQML及ROI版本与本地审核状态，不证明全左室代表性，也不提供独立MBF数值验证。没有真实工作站结果时，只导出空模板；绝不为真实样例填测试数值。

`case_token`为本次单病例目录所有Study UID集合的哈希，仅供临时关联，不是旧研究编号、不证明目录中所有检查属于同一患者，也不替代D5清单核对。方法、协议、审核者和参考均用无身份信息的代码；受控身份映射不进入输出。文件中不能添加姓名、患者日期、原UID或源路径。

### 14.3 参考、QC与保存

MR参考JSON严格绑定整个配对结果的SHA-256与方法ID，并提供`reference_id/reviewer_code/reviewed`及每项测量的`value/unit/atol/rtol`。模板参考值和容差为空；容差需独立预先约定。通过条件`abs(measured-reference) <= atol+rtol*abs(reference)`；失败保留误差，禁止标记为已核对。当前覆盖静息/负荷归一化斜率和MPRI；参考必须来自相同定义，不把不同工作站方法硬套为同一测量。该比较提供工程一致性证据，始终不设置`clinical_validated=true`。

MR/PET保存来源绑定、完整D3 ROI文档和输入曲线、方法/参数、单位及QC；MR不完整配对时先补齐两状态，缺PET或缺参考可保存MR配对预览，缺项明确标记。`perfusion_input_ready`要求两灌注分支本地QC通过且MR参考比较通过；工程体模或任一ROI/窗口/配对审核未过时为false。该标记不是临床效能验证；`model_input_ready=false`、`diagnosis_available=false`始终保持，三类融合与模型冻结在D5–D6处理。

界面保留结果随ROI/复核文档修改失效；病例切换清空，时层/序列/文档上下文过期的后台结果不发布。PET导入及特征保存前重新检查涉及对象的size/mtime，不读像素；来源签名和文件属性都不是内容哈希或匿名化证明。快照在`outputs/features/<UTC时间戳-随机ID>/`，规范`features.json`、`features.csv`全部成功且未取消才写`bundle.json`；8 MiB JSON上限，重复键/非有限JSON拒绝导入；失败残留保留、不覆盖旧目录。

验证链：已知非均匀曲线的峰值/时间/斜率/AUC/比值及拒绝路径→原生Windows Qt MR/PET工作流、源变化/旧任务隔离→复用D3两例工程曲线检查派生或合理拒绝→待补独立查看器/真实解剖和参考数值比较。`scripts/desktop/check_perfusion.py`默认只跑合成MR首过；可加`--roi-report`读取已通过D3的受控快照，不扫描影像。复用工程轮廓在固定基线下无增强时应保留拒绝，不能为了回归通过而自动调窗；报告通过仅表示工程合同执行符合预期。原生Qt反复创建测试窗口后须等待全部worker结束，再在GUI线程`deleteLater`并处理DeferredDelete，避免把图形对象留给后续循环垃圾回收；应用退出入口同样显式释放。

### 14.1 曲线定位与MR分析窗口

`desktop.curve_link.CurveLink`在统一窗口初始化后连接ROI、FeaturePanel及工作恢复通道，不另建DICOM读取/曲线计算流程。“灌注分析”增加同源原始曲线，两个图共用定位/基线/首过工具及当前参数；`perfusion.windows`为无Qt的采样时间检查、最近帧/区间映射和帧序关系校验。时间严格取当前层实际`times_s`并与曲线时间逐项相等，不能以横轴秒数直接充当帧号，不能把cine各层时间合并。

左键定位映射到最近实际采样帧，相同距离稳定取较早帧，再通过原时间滑块/后台加载请求调度；快点仍合并中间目标并落实最终位置。原图及其实线游标保留到新帧接受，分析图用虚线提示加载目标，不先改已显示帧标签。ROI编辑、来源/文档/层面错配、勾画草稿或工作保存恢复锁定期间拒绝交互；切换上下文取消未完成点选及拖动发布。曲线清除时清同源图/色带，不保留上例曲线。

MR用常驻LinearRegionItem标绿色基线和金色首过；开始选窗/拖动或修改窗口帧号会暂停播放。拖动边线/色带后吸附至实际采样帧，也可两次点选端点，第一点以紫线表示。数字框保持原从1计的基线起始/帧数及首过起止，映射为零基闭区间。基线至少2帧、基线结束严格早于首过起点、首过至少2帧且不超界；无效拖动/点选恢复原参数并提示，不移动另一窗口来凑合法。初始另一窗口本身未配置到序列范围时，允许先设置单独有效区间，完整组合合法后才启用MR计算。数字框可暂时无效，不静默修正；选择吸附后完全相同的区间不使旧结果或复核失效。

窗口参数改变后同步两图，清候选及当前来源/当前层面的保留MR、相关MR参考/配对确认，并将窗口复核置false；其他状态保留结果独立于当前编辑。临床协议/采集状态/窗口审核更改同样使当前候选和对应保留结果失效。更换源/重算曲线清当前窗口审核，不把旧审核勾选带到新序列；时间帧浏览不清相同层的审核。分析由显式按钮触发，不在拖动时自动计算，不自动选窗、估计临床最优窗或勾选审核。原MR数值公式/参考起点保持不变，图上着色不改变原始TAC或单位。

工作记录沿用schema v1及既有参数字段；恢复在来源/数值复算通过后，阻断参数控件信号一次性回填，再重建两页曲线/色带，保留记录中的审核状态。工具、点选第一端和拖动草稿不持久化。新PlotWidget的菜单显式Qt父对象并保留Popup标志，常驻色带/游标在clear后复用，关闭仍等待全部后台通道并在GUI线程释放。验证覆盖非等间隔与平局、真实鼠标选帧/拖色带、错误区间、待显示帧、迟到分析失效、PET/cine门禁及跨窗口/旧版本工作恢复；专业窗口选择与定量参考仍另行审核。

## 15. 用户侧人工验收步骤（T2–T4）

### 15.4 真实ROI与运动：影像医生审核，用户操作保存

1. 先做一个MR灌注平面。选择清晰参考帧，放置心肌参考轮廓，按医院规则调整外膜与内膜排除轮廓；再放置并调整血池。默认几何轮廓必须人工调整，不能直接当真实心肌。
2. 遍历该平面的全部时间帧；移动/呼吸导致错位时选“仅修正当前帧”调整。中间帧不会自动插值，未修正帧沿用参考；已有独立轮廓的帧在当前帧模式编辑。
3. 医生确认轮廓解剖位置、血池/心肌分离、越界/重叠、运动和可用性。无法可靠标注的分支记录不可用及原因，不强行通过。
4. 真实方向/覆盖和全部已标注层运动审核完成后，勾选ROI页对应两项，再点“计算原始曲线”。勾选/修改复核会使旧曲线失效，因此必须在最终复核状态下重算。
5. 保存ROI/曲线。每个序列的`roi.json`、`curves.json`、`curves.csv`及最后的`bundle.json`均记录新目录；换病例前务必保存。
6. 对匹配MR另一状态、PET两状态重复。PET本地单层ROI曲线只提供来源/时间/运动辅助检查，不能验证全左室工作站MBF；PET全左室质控仍需工作站审核。

### 15.5 MR基线、首过窗口及配对：医生确认，用户执行

1. 查看最终双ROI曲线，由医生/研究负责人确认有依据的增强前稳定基线及首过区间。基线至少2帧是软件下限，不是建议每例都只取2帧；起始过渡帧是否排除要记录理由。
2. D4页手动确认状态和协议代码；填写基线起始/帧数及首过起止帧。基线最后一帧必须在首过起始帧之前，结束帧不能超过该序列范围。真实病例不照搬合成1/2/3/7参数。
3. 窗口实际核对后，先勾“已按曲线核对基线与首过窗口”，再计算特征并保留。改变窗口/勾选会使未保留候选失效，须重算。
4. 同样完成另一状态。静息/负荷必须是对应解剖平面，不按层号或方向近似相同就算配对；医生确认剂量/序列/协议可比较后再勾两项配对复核，记录半定量MPRI。
5. 先保存一个平面对的结果；多个短轴及长轴分开做。当前每个状态只保留一个MR平面，后一次会替换同状态先前结果，没有多平面自动汇总。
6. 若提示`feature_no_positive_enhancement`，核查真实ROI、时间顺序、基线和首过依据；有明确错误才更正并记录原因。旧工程轮廓被拒绝不是患者无灌注或CMVD诊断，不反复调窗直到数字通过。

### 15.6 PET工作站结果：核医学/工作站人员配合

1. 索取同一检查经过工作站审核的全左室静息MBF、负荷MBF、单位、可用的MFR、示踪剂、算法/软件版本、协议代码及本地参考/审核者代码；同时确认动态图像、运动和曲线质控。保留原报告/导出作为受控引用。
2. 在本应用对PET静息动态序列完成最终ROI/复核/原始曲线；D4选择静息并保留当前PET曲线。负荷动态序列同样操作。不要用静态PET或门控序列代替动态分支。
3. 导出PET填写模板。保留`case_token`、两分支`binding`、schema和kind原样；将两项`mbf`填为真实工作站数值，`unit`只支持`mL/min/g`，`region`为`global_lv`。方法、版本、协议、示踪剂、参考、审核者填真实可追溯代码，不填姓名。
4. 有MFR填`reported_mfr`，未提供则保留null；质控负责人实际确认后才将`qc_passed`设true。模板中的`mfr_absolute_tolerance`须在比较前约定，不因不一致而临时放宽。
5. 导入工作站JSON，逐一对原报告核对静息/负荷MBF、单位和MFR。失败时核对状态颠倒、单位、值的舍入/定义、来源或过期ROI，不改签名绕过检查。
6. 此步骤证明导入/关联及比值计算；本软件未独立重建或验证MBF动力学。真实工作站结果尚缺时只能保留空模板，不填示例数字或勾选虚假QC。

### 15.7 MR参考比较：研究方法负责人配合

1. 固定ROI、两状态窗口/参数、协议及配对复核，再准备参考；之后任何改动都需重新计算及取得相应参考。事先约定比较定义与工程容差，临床/研究可接受误差另定。
2. 参考优先为能说明算法/窗口/单位的独立测量。当前算法是相邻真实时间点最大ΔSI/Δt，再取心肌/血池比、负荷/静息比；若工作站用多点拟合、其他归一化或绝对MBF，不能直接当同定义参考，记录差异交由适配。
3. 也可让第二人用`curves.csv`在Excel独立计算核对数学实现：各ROI在首过起始前一帧至各自窗口峰值计算相邻ΔSI/Δt最大值；分别求心肌/血池斜率比，最后负荷比/静息比。必须用`time_s`，不能用帧号。此法不是独立解剖/原始信号或临床效能验证。
4. 导出MR参考模板，保持方法及`feature_sha256`不变；填写静息/负荷归一化斜率和MPRI的参考值、单位`1`及预定`atol/rtol`，附参考/审核者代码。实际完成审核后才设`reviewed=true`。
5. “核对MR参考结果”，保存每项误差及通过/失败。不同定义或缺参考时保留未验证；不得拿软件自己的输出复制为参考。

### 15.8 保存、拒绝路径与复现：用户可独立完成

1. 同一病例中完成MR配对和PET结果导入后保存特征/QC。确认新目录包含`features.json`、`features.csv`、最后的`bundle.json`；临床/模型/诊断标记当前仍为false是预期。
2. 先留好正常证据，再以输出副本测试：A病例ROI加载到B应拒绝；PET JSON副本改成错误单位应拒绝；ROI修改后旧曲线/相关保留结果应失效。绝不改data/原件或真实报告制造异常，不把测试副本当正式研究记录。
3. 重启，打开同病例的相同序列，逐一重载已保存ROI，按已保存复核/窗口/协议重算及保留MR/PET，再导入对应工作站及MR参考。当前没有完整特征快照一键恢复按钮；需要恢复各序列ROI及参数。

5. 同样完成第二开发病例并扩展剩余MR平面。每项记录病例受控引用/开发别名、序列/层/时间范围、操作、预期、实际、状态、审核代码、软件版本及快照/错误码；在受控outputs中保存测量证据，HANDOFF只保留摘要与入口。未做的项填待核对，不写通过；影像/含身份截图不发公开日志。

### 16.4 D4复算与合成隔离

检查D4同目录完成标记、canonical JSON哈希、病例token与人工关联；从保存的ROI/曲线/真实时间、单位、基线/窗口复算MR两状态及配对；PET重新从工作站结果/本地TAC导入；同定义MR参考重新比较，完整bundle须逐项一致。只改测量或QC，即使重写文件哈希也无法跳过复算。真实模式下工程体模、未审核ROI/窗口、错误单位、来源错配或缺参考不得成为完整行。

复算只针对保存快照，不重新读DICOM；绑定不是像素内容哈希，不独立验证工作站MBF或证明人工审核真实性。`measurement_reviewed`仍须在实际审核后填写。

完全合成队列用`mode=synthetic_fixture`和`SYNTH-*`研究/患者代号：8次检查、7位患者，6位均衡开发患者、1位独立保留及1次同患者附加检查。已知信号给出PET MFR≈3/MR MPRI≈2，所有临床值/诊断/工作站数字虚构。合成路径允许保留`engineering_fixture`及D4就绪false的比值仅进入**合成工程矩阵**，不改D4标记。`perfusion_usage=synthetic_fixture_values_only`，真实训练就绪始终false；真实模式拒绝SYNTH编号和工程体模。

### 16.5 患者划分与冻结

独立患者由事前审核划分表明确指定，不自动随机挑取；全部检查只保留编号/患者/用途/保留原因，不评估临床数值或诊断内容、不打开其D4特征、不进入开发features.csv、labels.csv或折集合，不报告独立标签分布。共享CSV仍需解析结构、关联键及完整性哈希，独立语义值不用于筛选或开发统计。

开发完整行按患者分层确定性划分，默认3折/种子20261020：每类按`SHA256(seed:patient_key)`排序后轮流分折。训练/验证患者不交叉，独立患者不出现；任一类少于折数记`insufficient_patients_per_class`，不默默降折。工程拆分不保证小样本统计效能。

项目policy记录病例对账、临床合同、诊断定义、纳入排除的人工确认及引用代号。`reported_case_count`默认80，必须与旧清单次数一致；若正式对账确认应为79，人工修改并保留引用，不由程序自动消除差异。检查数和患者数分别报告。

“校验并锁定患者划分”需清单/关联覆盖、唯一选定检查、对账/用途/审核完成、至少1位开发及1位未开发独立患者。允许在临床/特征未齐时先冻结患者用途防止误用独立患者，此时训练仍不就绪；冻结不会改变缺失或失败QC。

普通审计写`partition_plan.json`；明确冻结写`partitions.json`，绑定审计/输入/合同/配置哈希、患者全部检查及折策略。D6需显式选一个完成版本，用`cohort.storage.load_frozen`核对，不能混用不同版本矩阵/划分。新增资料需重新审计时另产版本并确认研究方案，不覆盖既有工件。

### 17.1 已确认的数据安排与论文适用范围

用户2026-10-20确认：现有约80例之外能再补40例独立验证。由此确定**80例开发＋40例独立测试**的研究安排；这是可补充的计划，不表示120例已到位，也不把数据包数直接当独立患者数。当前79/80对账、旧编号/患者关联、医生标签/定义、临床表和D4真实测量审核仍缺，不能现在直接把80份影像送入真实融合训练。所有纳入人数按实际患者及完整资料报告，不能补造缺失者凑80。

参考用户本地Singh等论文，DOI [10.1016/j.jcmg.2022.07.017](https://www.jacc.org/doi/10.1016/j.jcmg.2022.07.017)（2022在线，2023卷期）。本地PDF SHA-256为`215cb906f2908337ab441dc29388f5941b42ea3de31784f59d81924949c7d899`。已读取本地Methods/网络图相关文本并与出版方/PMC页面对照；标准库提取丢失排版、字体及分词，不等于逐页渲染或补充材料完整审查。

### 17.2 模型范围与开发顺序

**A线：先完成可交付的低维融合基线。** 沿用候选合同`d5-candidate-v1`的8列：年龄、高血压、糖尿病、吸烟、静息心率、LDL-C、PET MFR、MR MPRI；三类输入均进入同一正则Logistic。字段及单位仍需医院确认；不自动从DICOM补年龄/性别，不以标签目录填值。危险因素/临床这两组用于分组解释，模型上可以合并表格，不必人为做两个神经网络。MFR和MPRI不互换；CFR导出需核对定义/方法/区域。若标签本身完全由同一MFR阈值定义，先审查循环定义偏倚，再锁定参考标准/主特征，并预登记去MFR敏感性分析。

主线拟用scikit-learn Pipeline/ColumnTransformer：连续量仅在当前训练折StandardScaler，0/1字段保持编码；不自动筛选高维影像组学，不做全队列单因素筛选或先做SMOTE。完整病例策略沿用D5：任一必需临床字段、PET或MR分支缺失都明确排除并报原因，不填0。以后若引入临床插补，须新合同、训练折拟合和单独敏感性分析，不能静默改D5策略。

工程初值：`LogisticRegression(solver='lbfgs', l1_ratio=0, max_iter=2000, tol=1e-6, class_weight=None)`；内层只比较`C=[0.01,0.1,1.0]`。按内层平均log-loss选择，数值相同时选较小C；不直接采用训练准确率/外层测试AUC调参。本机scikit-learn 1.9.1已只读核对构造签名及fit源码：L2用`l1_ratio=0`，避免新代码传已弃用penalty参数。这些是本项目预设，不是论文报告的参数。

**B线：论文启发的小型双分支CNN，作为预登记的探索对照。** 保留在训练计划中，但其原始图合同、源图生成和解剖审核是额外前置任务，目前D4只有ROI曲线/数值快照，不存在可直接训练的标准灌注图队列。D6-A交付不依赖B线胜出，不承诺CNN优于Logistic。若验收要求必须包含CNN，应按B线单独交付与报告，不能把A线宣称为深度图像融合。

候选B线结构如下（本项目设计，不冒称作者官方实现）：

```mermaid
flowchart LR
  P[PET静息/负荷经审核灌注图] --> PC[两层小型2D卷积编码器]
  M[MR静息/负荷经审核半定量灌注图] --> MC[两层小型2D卷积编码器]
  C[6项临床与2项审核灌注比值] --> S[折内连续量标准化]
  PC --> F[特征拼接]
  MC --> F
  S --> F
  F --> H[小型全连接层]
  H --> O[CMVD阳性分数与二分类]
```

B线拟先用固定32×32心肌极坐标表达、各模态静息/负荷2通道；PET为审核工作站MBF空间图，MR为同定义归一化上升斜率空间图。需另行验证空间图导出/单位、方向、心肌掩膜、短轴层面与覆盖、静息负荷对应、运动及MR像素级算法；原生定量与显示/重采样通道隔离。没有这些空间图就保持B线输入未就绪，不能将全局MFR/MPRI平铺成图片、拿cine/静态SUV代替灌注或强制把长轴当短轴。此图合同是实施候选，需用开发病例验证后版本化冻结，不能边看40例结果边改。

每个编码器初值：Conv3×3(2→16)→GroupNorm→LeakyReLU→MaxPool2→Dropout(0.2)，再Conv3×3(16→32)及同类操作，最后全局均值池化，得到32维；两个32维向量加8项表格输入，经16维全连接/Dropout(0.3)输出1个logit。小批量用GroupNorm是本项目调整，与原文BatchNorm不同。默认AdamW、lr=1e-3、weight_decay=1e-3、batch=8、最多100 epochs、内层验证log-loss早停patience=15；按内层最佳epoch汇总确定外层重训epoch，不用外层或独立40例早停。默认不翻转/旋转极坐标图、不随机改变定量灌注强度，后续增强必须先确认解剖/物理含义并只在训练折使用。初值不是已验证最优值；任何调整限预登记的开发过程。

### 17.3 80例开发的具体训练链

1. **冻结研究定义与输入版本**：对账79/80、医生标准/判定时点、患者身份/多检查/index_exam、8项字段/单位、缺失排除及D4审核；报告实际患者数、医生阳性/阴性数、完整病例及各缺失原因。先审核后纳入，不把目录31/48分组直接当医生标签计数。
2. **登记两个队列的用途**：现有合格患者进入development；新增40例进入independent_test。两例历史调试样本仍只属于开发。新增40例全部检查不用于选ROI/窗口规则、图像模板、特征、标准化、模型、超参数、早停、阈值或校准；固定规则下逐例处理与QC允许，失败如实记录。
3. **外层3折内部评估**：沿用D5患者级确定性分层计划、seed=20261020，不重排原编号。80例完整时，每外折约53/54训练、26/27留出；每人仅一次外层OOF预测。多次检查/切片/时相不拆分。少数类别或内层数量不足直接报方案不可执行，重新登记折方案后才运行，不静默改折数。
4. **内层3折选择**：只在外层训练患者内划分，学习标准化/任何预处理并选择C；若运行B线，所有epoch/超参数选择也在内层。外层留出只做预测/计分。不能用同一层交叉验证同时选最好模型并声称其分数无偏；若要自动选择A/B模型族，须将模型族纳入内层选择，外层评估整个选择流程。[scikit-learn嵌套验证说明](https://scikit-learn.org/stable/auto_examples/model_selection/plot_nested_cross_validation_iris.html)、[Pipeline防泄漏说明](https://scikit-learn.org/stable/common_pitfalls.html)。
5. **生成可追溯OOF报告**：A线主分析预先指定，B线结果为探索对照；以相同患者/相同折做临床、临床+PET、临床+MR、全融合消融。只在所有模型共同完整的患者集合比较增益，另外报告覆盖率，不比较不同患者子集的AUC后归因模态。指标含ROC-AUC、PR-AUC、敏感度/特异度、平衡准确率、混淆矩阵、Brier及校准描述；单类别指标记不可计算。患者级bootstrap区间需注明固定OOF预测未覆盖全部训练/选择不确定性，不能把折/重复当独立样本做显著性检验。
6. **锁阈值与最终拟合**：首版预先固定阈值0.5作为工程分类规则，不能称临床阈值。若医院要求目标敏感度，应事前确定目标，并只在内层选择阈值、由外层评估；最终阈值由开发内部预测确定后冻结，不从40例调。确定模型族/变量/参数选择规则后，在全部合格开发患者内部选择最终参数，再用全部开发病例拟合最终管线；B线用开发内层最佳epoch的预定汇总规则固定轮数重训，不看独立标签。
7. **冻结模型包**：保存合同/单位/字段顺序、预处理、系数或权重、阈值及依据、标签定义、患者划分引用/数据哈希、源代码/依赖/随机种子、训练及OOF报告、适用范围和失败门禁。确认保存重载/CLI推理一致，模型不含独立40例统计量。交付模型的训练集自身准确率不当验证性能。
8. **新增40例一次性评估**：模型/特征/阈值冻结后，用同一管线运行并保存首次预测和参考诊断，纳入/排除与QC失败都报告。40例仅是独立测试；若来自同院后续时间是时间验证，来自独立中心才进一步讨论外部验证。性能区间可能宽，40例也不自动等于临床充分验证；是否足量需依据病例构成和目标精度评估。不能从40例中挑最好模型/阈值后仍称该队列独立；若用它更新模型，需另取新的独立测试队列。

80例因此可全部进入**开发过程**，而不是每一折同时训练并评估同一人；最终模型可在80例均合格时用全部80例拟合。临床表/标签/测量暂缺时只做合成训练管线及防泄漏测试，不能宣称已训练真实模型。

### 17.6 D6 A线训练接口与冻结合同

**队列协议。** `configs/cohort_project.v2.template.json`显式使用schema_version=2；v1模板/输入/旧快照不改写。版本2的`population_protocol`包括协议代码、开发/独立患者目标、开发人群已核对标记/引用、独立登记状态及引用。pending要求独立登记为0；partial要求0<登记数<目标；registered要求登记数达到目标，后两种须有审核来源引用。开发人群未核对或登记状态与人数不符时不能冻结。患者目标不是检查数；现有清单检查数仍按`reported_case_count`与实际清单对账，开发/独立登记数和合格开发数另报，未到目标不静默补人。目标差额经原对账/排除审核明确保留，不等于自动认定已达到80。冻结开发不证明独立验证已完成。

**输入。** `training.load_training_data`先调用原`cohort.storage.load_frozen`检查完整D5工件及哈希，再核对审计就绪、协议/字段合同、列顺序/单位、医生标签定义、唯一患者/index_exam、开发行/标签集合、患者折和模式。训练不读取原始影像或独立值/标签；合成需`allow_synthetic=True`，真实模式仍须D5真实training_inputs_ready及D4来源。原6位开发患者的D5演示可冻结但不足3×3嵌套所需的内层类别人数，D6明确拒绝，不自动降折。

**算法。** `configs/training_contract.json`固定4组输入、3×3患者折、seed、C=[.01,.1,1]、L2/lbfgs与0.5工程阈值。外层严格复用D5冻结患者折，每位患者一次OOF；所有消融使用同一批完整患者/标签/折。内层仅在外层训练患者内调用原`make_folds`；每个候选每折单独拟合ColumnTransformer/StandardScaler与Logistic，二元字段原样通过。连续量零方差的scale为1。内层平均log-loss最小者入选，完全相同取较小C；外层留出及未来独立40例不参与选择。任何内层类别不足、求解未收敛或取消均不放行。最终在全部合格开发患者内部3折选择C并重训，不用训练集准确率当效能证据。

**评价。** 保存ROC-AUC、average precision（阶梯积分，不冒称梯形PR-AUC）、固定阈值敏感度/特异度/平衡准确率、混淆矩阵、Brier/log-loss与5个固定概率区间的校准描述。按患者对固定OOF预测作1000次百分位bootstrap，区间仅描述固定预测重采样，未覆盖模型训练/选择不确定性；单类别重采样跳过且报告数量。主模型预指定fusion，不从外层结果自动挑消融赢家。合成结果不作临床评价。

**存储与推理。** `training.train_snapshot`在`outputs/training/<UTC-随机run>/`独占新建，先写attempt，最后完成bundle。工件为training/feature合同、models、report、fold_audit、oof_predictions和provenance；所有文件字节哈希由bundle绑定，输入快照/字段/训练合同/标签定义/代码与Python/numpy/scipy/sklearn版本可追溯。只保存JSON数值的均值/尺度/系数/截距/阈值，不使用pickle。所有输出为受控资料、Git忽略；不输出原患者路径/UID。每个折和最终模型的数值表示与sklearn预测误差须≤1e-12；实际磁盘保存/重载前后数值预测须完全一致。保存后再次核对D5工件、代码及配置未变，任意失败/取消保留failure/partial且无完成bundle，不覆盖旧run、不自动恢复。

`training.load_model_package`只接受完整且哈希/字段/单位/来源绑定有效的模型包，合成模式默认拒绝。`training.predict_features(model, features, units, feature_contract_sha256=..., allow_synthetic=False)`按显式字段名取值，严格核对字段集合、单位、合同、有限值/范围，输出阳性分数和`p>=0.5`二分类及合成/未临床验证标记。该纯数值函数不能替代D5/D7的病例来源/特征审核；桌面诊断接入尚未实施，也没有独立40例评估接口。外层模型/最终系数和OOF记录仍是受控研究资料。

CLI：`scripts/demo/train_model.py --synthetic-demo`先复用D5合成生成器，建立80位虚构开发患者＋1次附加检查、变化的合成临床/PET/MR已知真值，不生成独立患者；审核/真实训练标记仍保持合成。经原D4复算/D5校验冻结后执行相同训练/保存/重载链。真实入口仅`--cohort <明确的真实冻结D5目录>`，不接受目录前缀标签或任意裸CSV，不能通过真实命令加载合成快照。测试与运行结果见HANDOFF。

## 18. 原始压缩包的分批解压与工程检查

### 18.1 工具和输出规划

使用[7-Zip官方下载页](https://www.7-zip.org/download.html)指向的官方release便携`7zr.exe`，固定26.04，放在`E:/Conda/tools/7zip/26.04/`；来源URL/下载SHA-256记录在工具缓存及HANDOFF。不修改PATH、注册表或Python依赖；可执行文件未签名，只能称核对了官方HTTPS来源、本地版本与固定哈希，不能称Authenticode发布者已验证。

`scripts/data_preparation/extract_and_inspect.py --plan`只枚举data/下一层的7z包、计算源SHA-256并调用`7zr l -slt`。完整原始路径/成员/时间等只写`audit/restricted/archive_extraction/<run>/`；计数、体积和固定错误码预检写`outputs/archive_validation/<run>/preflight.json`。临时ARCH token由包相对路径哈希产生，不继承POS/NEG身份、不推导目录诊断、不是新的患者清单。旧研究编号/同人多检查仍须原映射审核。

### 18.2 预检、安全与冲突处理

预检拒绝绝对/UNC/盘符路径、父目录穿越、Windows ADS/设备名/不明确尾点空格、链接/重解析点、加密或anti成员以及文件/目录冲突。大小/文件数有界，并以总解压字节＋每文件4 KiB开销＋20 GiB余量核对可用空间；每批再检查10 GiB保留空间。工具与源包哈希/size/mtime绑定；解压前后复核源包哈希，保留源不变证据。全部输出只进入新目录。

普通成员采用`-aos`且目标必须从未存在；不会默默复用中断目录。发现**完全同名文件成员**时仅在列表包含明确CRC、且不是大小写/目录/链接混淆的情况下，明确登记`auto_rename_preserve_both`，使用7zr `-aou`将新成员改名保留两份；随后核对实际全部文件数/逻辑大小，并逐一读取冲突候选的CRC/大小，证明两份都保留。成员→输出路径映射只在restricted中，不改变压缩包、内容或患者编号。该路径冲突不自动等于两个独立临床对象，后续SOP/网格检查仍会报重复等异常。

提取进程的原始stdout/stderr只进restricted日志；公开控制台仅计数/固定错误码。退出码为0后仍核对文件集合/大小/无链接，再做D1检查。当前工具没有中断病例自动续跑；任何已尝试目录或逐包记录会拒绝覆盖整个请求批次。中断/失败保留原目录及日志，重试须显式新run或另行设计带来源对应的新attempt，不能删除残留伪装成功。

### 18.3 检查范围和报告语义

读取复用`cmvd_demo.io.scan_case/build_grid/build_cine_stack`，不另外实现DICOM解码或强制容忍坏头。检查每个解压文件的头字段；按现有支持分支组装PET动态/静态/门控、MR灌注/cine网格，并对每网格首末位置读取逐对象缩放后的float32像素、有限性/形状和哈希。短轴cine只在相同Study和几何候选内尝试合并，合并失败保留原因，不补帧或强制同步。其他MR/截图/多帧等按读取器支持范围仅索引，不声称像素通过。

## 19. Windows桌面发布包与运行验证

### 19.1 包形式、依赖和数据边界

采用PyInstaller固定版本6.22.3的Windows x64 onedir模式：`CMVDBrowser.exe`及同目录`_internal/`整体发布，再压缩成ZIP。使用同一`scripts/desktop/run_desktop.py → desktop.launch.main`入口，不复制另一套读取器或Qt窗口。程序不依赖目标电脑的Python/Conda，不自动启动训练、接入模型或扫描病例目录。该包是本机研究浏览器预览，是否可在另一台电脑启动须另外测试，不把本机成功称为跨机器认证。

运行依赖仍见原`windows-py312.lock`，本轮不修改已安装研究环境。打包依赖另放`requirements/build.txt`及`windows-build-py312.lock`，安装到项目外独立工具target；构建子进程才添加工具PYTHONPATH及Conda Library/bin到PATH，以解析ffi/bz2/lzma/expat等CPython动态库，不改全局PATH。下载文件按官方PyPI发行元数据SHA-256核对，固定wheel哈希；实际工具位置/来源证据记HANDOFF。PyInstaller/Qt相关方式参考[官方使用说明](https://pyinstaller.org/en/stable/usage.html)及[运行原理](https://pyinstaller.org/en/stable/operating-mode.html)。

构建仅收集`paths.RESOURCE_FILES`明确列出的公开配置与6份空CSV模板；模板须仅有表头，项目模板不能携带绝对本机输入路径或已审核真实策略。不加入data/deidentified/metadata/audit/outputs/models、runtime.local.json、训练模型或真实病例。包内提供使用说明及运行依赖的上游许可证/版本资料。没有发布者数字签名，不声称已签名。PyInstaller默认pydicom hook会收集公开示例DICOM，因此使用自有小型hook省略所有示例/调色板文件，并在运行时只禁用未使用的pydicom.examples入口；保留像素处理所需pydicom.data代码，不改变原始读取、缩放、几何或定量算法。已有支持范围仍为原生单帧单色MR/PET等；未验证的彩色/压缩等范围不因打包而扩展。

### 19.2 资源与可写工作目录

`cmvd_demo.paths`集中解析路径。源码运行默认仍以项目根目录为workspace；冻结包内`_MEIPASS/resources`只提供公开资源。冻结版默认工作目录为`%LOCALAPPDATA%/CMVDResearchBrowser/workspace-v1`，可通过`--workspace <本机可写目录>`覆盖。首次只复制缺失的白名单资源，不覆盖已有模板/配置，不创建病例编号/临床数据。已有配置和新包资源版本不一致时，另行审核迁移，不能静默替换。文件菜单“打开工作目录”用于定位保存和日志；ROI/D4/D5全部使用同一workspace，不写exe旁或打包临时目录。仅拷贝程序ZIP不包含历史研究输出，迁移研究结果需另备份受控workspace。

## 20. 结果保存与工作恢复

### 20.1 操作与范围

顶部“保存工作／恢复工作…”及文件菜单管理当前病例的手动保存点；灌注分析中的“保存当前MR分析”允许单个静息或负荷状态独立保存，不要求先配成MPRI或补齐临床数据。单状态记录只包含活动序列ROI、当前层曲线/分析和参数；不会隐式把候选结果加入静息/负荷保留槽。病例工作记录包括所有已标注序列ROI、活动层及保留结果引用的曲线、MR/PET保留槽、已导入PET结果、MR参考及界面设置。未保留的历史计算结果、撤销栈、运行中的任务与播放状态不在恢复范围内。

恢复前用户须显式打开原病例或对应合成演示，记录不存患者源路径，也不复制影像。恢复会替换当前病例的未保存编辑；统一未保存工作保护见第23节。活动帧/层面、窗宽窗位、视图范围、浏览帧率、工具、页签及滚动位置随记录恢复。不同窗口大小下，视图纵横比例/滚动位置受布局约束。保存点支持关闭后继续工作，不是自动保存或崩溃恢复服务，也不承诺重新导出影像、更改病例目录内容或跨电脑后仍能匹配。

### 20.2 文件合同与复算

`cmvd_demo.work`为无Qt核心，复用现有`ReaderBackend`、ROI绑定/曲线与灌注函数。`save_record`每次新建`outputs/work_records/<UTC-随机run>/`；先写未完成尝试记录，核对并复算后写`work.json`、活动序列`roi.json`、可选活动层`curves.json`及确定顺序的MR测量表`measurements.csv`，最后写`bundle.json`。中断或失败保留残留且无完成标记，不覆盖旧保存点。所有文件SHA-256写入完成标记，沿用单JSON文件8 MiB限制；每条记录最多64个序列条目。

`work.json`的`schema_version=1`、`kind=image_work_record`、`scope=case_work|single_mr`。`case_token`复用现有病例来源摘要；`active_key`和`entries`复用现有安全序列key，不创建患者编号。每条entry含完整ROI文档和按零基层面索引的曲线。`view`保存浏览设置；`feature_state`包含`settings/candidate/mr_slots/pet_slots/pet/mr_reference`。UI窗口参数保存为从1计数的帧位置，数值算法仍用原零基索引；保留结果中的grid不序列化。原始路径、姓名和原始UID不写入记录，但ROI、曲线及来源元数据仍属受控研究资料。

`load_record`只接受记录目录或其中的`work.json/bundle.json`，要求完成标记、固定文件集合、大小限制及逐文件哈希；核对活动ROI/曲线副本与JSON，并核对CSV可由JSON确定复现。`restore_record`先在后台验证全部候选条目：原病例摘要、已有序列、完整来源绑定、LPS几何、实际时间、单位及源size/mtime；仅重建记录所需网格，逐个已保存层从原图复算曲线并与保存结果比较，再用原参数重算MR、重新校验PET工作站输入与MR参考。发布前再核对源文件状态与记录文件，拒绝处理中变化、缺失、错配或复算不一致；不补帧、插值或修改原件。以上文件哈希和选定曲线复算不是全影像逐像素内容哈希、全面匿名化或临床验证。

### 20.3 后台与发布

`desktop.work_controller.WorkController`拥有第六个独立后台通道。GUI线程深拷贝不可变保存请求；保存和恢复期间暂时锁定影像/分析编辑，文件菜单仍可协作取消。病例切换、ROI/曲线/参数变化使任务失效；保存发布前再比对病例版本、活动序列/位置及ROI/分析摘要，关闭窗口须等待包括本通道的全部任务后再在GUI线程释放原生对象。不得强杀线程。

恢复只有在全部来源和数值验证通过后才应用到GUI，复用窗口原`_accept_grid/_accept_plane`及面板`present_curves/present_mr/present_pet`呈现入口。文件损坏、错误病例和取消均不应用候选记录。恢复后的ROI编辑继续触发原有曲线/特征/审核失效规则；复核状态原样保留，工程体模不能升级为解剖标注或已审核训练输入。完成标记的`model_input_ready/clinical_validated`固定false，`kind`与完整双灌注特征包区分；原队列准入和训练冻结接口保持原规则。

原生自动验证覆盖跨窗口保存/恢复、已知合成真值、单MR和全病例、生成DICOM的PET本地曲线/工作站结果、错误/变化来源、文件改写、取消、换病例、关闭与恢复后再编辑。发布验证另在实际exe中保存后退出，以中文/空格路径的解压副本启动新进程，读取前一进程的合成工作记录并复算恢复。真实样例仅做明确限定的来源/ROI/曲线复现回归；独立方向对照、专业解剖/运动与定量审核另记HANDOFF，不由自动保存测试代替。

## 21. 序列状态与问题清单

`sequence_review.SequenceReview`是无Qt的当前病例工程记录，复用`Choice.key`及现有病例摘要，不另建病例清单。左侧状态为未预览、读取中、已预览、读取失败、部分读取失败、已取消、仅索引；状态由当前读取器的已接受结果驱动，预取不算预览。显示过某帧后别帧失败保留为部分失败；仅相同失败帧重试成功才解除该条当前故障，历史保留。网格失败由同序列网格重建成功解除；其他帧成功不能抹除失败。状态不代表解剖审核、全像素检查或训练准入。

`desktop.sequence_panel.SequencePanel`提供筛选、整个病例/当前序列问题表、双击/按钮定位重试、固定枚举本地处置以及历史提示。支持范围外的对象可选中查看仅索引说明，不调用其像素读取。头字段读取/解析失败按现有安全文件token列为未归属，不由文件名猜所属序列。定位失败帧先重建网格，再在范围内跳转原帧/层面；越界停止跳转，病例/序列变化拒绝迟到目标。处置是待核对、需医院核源/补导出、暂缓处理，不含“临床通过/已修复”选项。

每次“导出状态与问题”捕获点击时刻的不可变快照，在`outputs/sequence_reviews/<UTC-随机run>/`写`attempt.json`、`review.json`、UTF-8 BOM `issues.csv`，全部成功并再次检查取消后最后写带SHA-256的`bundle.json`。不覆盖既有结果；中断/异常保留未完成目录。schema版本1、kind=sequence_review，内容为安全病例摘要、序列key/kind/对象数/采集状态候选/当前状态/已接受位置/网格shape、固定问题代码/阶段/帧层面/文件token/来源/历史SHA/处置及有界事件，固定`all_pixels_checked/clinical_validated/training_ready=false`。不写姓名、原UID、源路径或异常自由文本；记录仍是受控研究资料。最多2000条问题、256条事件、每序列2048个显示位置，超限数量或截断标记显式记录，不声称完整访问日志。

`load_history`只接受同目录完成bundle中哈希有效的单JSON（8 MiB与记录数量限制，读取前后再核对）。既有逐包工程报告按原始Series安全token集合严格匹配；旧会话记录按已有case_token匹配。仅白名单代码、文件token和可确认的当前序列/帧位置进入历史提示，不复制患者字段或任意文字。组合cine的历史网格临时编号不能强映射到当前组合；未确认归属保持病例级。临时去重索引报告仍提示重复/零缩放等剩余问题，注明历史索引来源；报告成功不转成当前预览或已审核状态，不实施去重、补帧、插值或原件重写。历史处置结论不自动恢复；需要时另行本地记录。

报告导入/导出使用第七后台通道，协作取消、病例版本守卫，窗口关闭等待全部通道结束再在GUI线程销毁。问题表仅在内容或筛选变化时重建，逐帧播放保持表格对象。状态记录独立于影像工作记录v1，恢复工作只记录本轮实际接受的网格与帧，不把旧访问记录当当前通过证据。验证使用合成故障和原生Qt交互，真实回归明确限定样例/分支；具体结果、失败与人工审核缺口只记HANDOFF。

## 22. 静息负荷对照与研究记录

`desktop.comparison_panel.ComparisonController`是同病例双侧只读窗口。每侧复用`ReaderBackend`，拥有串行后台通道、一个可替换待办和16 MiB的平面缓存；两侧的序列、帧、层面与显示窗独立，不改变主窗口文档。新序列/错误清理旧内容，同网格等待保留最后接受的图像和对应标签/ROI，快拖合并并落实最终位置。关闭对照取消其请求，病例切换/主窗口关闭拒绝迟到结果。方向、LPS层面中心和单位分别显示；候选状态不代表医院确认，同一序列或异类型/单位只作独立查看。

`comparison.relative_target`按每侧当前层的实际时间减去该层首采样时刻，再选最近目标采样，平局取较早帧；超出目标范围停止联动，不夹到末帧、插值或补帧。默认关闭。仅MR灌注、PET动态及明确合成时间轴可联动；cine、门控或含心动触发意义的轴不作相对时间联动。层面始终独立，时间联动不表示解剖配准、生理同步或协议可比。

轮廓由主窗口已有文档及该侧真实网格绑定匹配后显示，使用三个常驻只读线对象，半像素约定与原编辑器一致。曲线只取当前结果或有效保留槽中来源/文档/层面匹配者，不另解码计算，也不混合两侧时间/单位。测量表显示有效保留MR全部测量，重点值优先，其他可滚动查看；显示名称由无Qt的`perfusion.labels`提供，不改内部字段或数值。ROI/窗口变化沿用原保留结果失效逻辑，不复制ROI或自动勾选审核。

`research_record.save_research`在`outputs/research_records/<UTC-随机run>/`独占新建，捕获点击时的原工作请求、序列问题快照及已接受对照位置。复用`work.save_record`生成`work/<子run>/`，保持image_work_record v1与其来源/曲线/分析复算合同；额外核对对照网格绑定及所选像素，并在外层完成前复查所有工作来源size/mtime。输出`attempt.json`、`research.json`、`summary.html`、UTF-8 BOM的`measurements.csv/curves.csv/sequences.csv/issues.csv`，最后写递归文件哈希的外层`bundle.json`。任一失败/取消保留部分且无外层完成标记；嵌套工作记录可先完成，不代表整个研究导出通过。单文件限制8 MiB，超限报错不截断CSV；沿用序列记录的问题/事件/位置有界限制和显式省略标记。

research_record schema版本1包含case_token、软件版本、嵌套工作记录相对路径/规范哈希、序列记录及对照快照；对照条目为已有安全key、来源绑定、帧/层面、显示窗及可选ROI/曲线哈希，未接受的失败侧不伪造有效位置。JSON与CSV保留`synthetic_data`；临床验证、模型准入和诊断可用固定false。CSV保留原始时间、帧长、单位、像素数和面积，索引从0计；摘要/界面从1计，摘要列实际测量、窗口与待核对状态。MR配对不满足时仍可导出个别研究草稿，但不补造比值。PET数值来自原工作站适配结果。CSV文本对公式起始符作转义，HTML转义动态值，不含外部脚本/资源；不导出影像像素、患者源路径或新增患者编号，全部输出仍按受控研究资料保管。

`load_research`要求完整外层标记、固定文件集合、受限相对路径/无符号链接及文件哈希，调用原`work.load_record`，核对派生CSV和固定v1摘要内容、前后文件未变化；这里只核对工件一致性，不重读影像或进行临床审核。摘要格式/字段合同升级不得静默破坏旧schema，应显式版本化。恢复按钮仍经原`work.restore_record`核对当前病例并从原影像复算；研究导出的对照位置和问题处置仅为快照，不自动恢复为临床结论或当前通过证据。

`desktop.research_controller.ResearchController`为第十后台通道（前七通道保留，第八/九为对照）。GUI捕获不可变请求，导出暂锁编辑并在发布时再次核对病例、工作文档/位置、序列版本与对照选择；工作保存/恢复与研究任务互斥。换病例、关闭或取消后不得发布旧结果；全部十个通道结束后GUI线程DeferredDelete。产品帮助提供简要操作，完整手动步骤及预期结果见[使用核对清单](USAGE_CHECKLIST.md)。自动工程检查与用户/专业审核分别记录，不自动填写人工验收通过。

## 23. 未保存工作、窗口关闭与错误诊断

`desktop.unsaved.UnsavedWork`统一保护退出、病例/合成切换与工作恢复替换。通过ROI文档、保留分析及参数的规范摘要比较完整保存点；未完成草稿和无效编辑也需保护。提示提供中文“保存工作／放弃修改／取消操作”，默认取消。选择保存使用原`work.save`后台通道，完整病例工作保存或研究导出成功后才更新保存基线；单MR或ROI单项保存不能把整个病例标为已保存。保存失败/取消不执行后续动作；继续动作还要核对病例版本和摘要。撤销回保存内容可恢复一致，不引入自动保存或新的影像/患者合同。

新病例先检查目录，再复用原主读取通道后台索引；读取期间暂存旧像素/位置、隐藏旧图，旧ROI/曲线/分析文档保留，通过独立取消进度窗管理。索引成功且存在序列才提交病例替换；失败、空目录或取消恢复旧显示，不将新病例索引失败写成旧病例序列失败。像素分支仍按原严格规则检查，不因目录有效而放行。阶段内部保留的旧工作不作为新病例结果发布。

病例进度窗在构造和任务完成、失败、取消时调用`reset()`停止Qt内部延迟显示计时，再隐藏；新任务开始前重新初始化。仅`hide()`不足以停止`QProgressDialog`的延迟显示。启动检查必须超过默认4秒延迟阈值，并确认未提交病例索引任务；发布包普通启动观察8秒，防止空闲时显示假读取状态。

`desktop.dialogs.TaskDialog.done`统一接受Qt的Close、Esc/reject与程序关闭路径，通知研究/序列/对照控制器协作取消、使发布上下文失效；主窗口仍等待全部后台通道完成并在GUI线程DeferredDelete。研究窗口关闭会解锁主编辑，等待后台实际结束期间仍不提交冲突任务。取消不能撤回此前已经完整提交的不可变记录，不通过删除旧完成标记伪装取消。

主工作区与研究窗口使用滚动容器，布局尺寸按当前屏幕可用区域设置；小窗口/高缩放时通过滚动条访问完整操作，不压缩按钮到文字不可读。影像/ROI坐标、来源绑定、计算值及原存储schema不变。

`desktop.diagnostics`在后台捕获失败时写`outputs/runtime_logs/<运行标识>-events.jsonl`，仅含运行UTC、固定阶段与经字符/长度约束的错误码；不写异常字符串、堆栈局部变量、患者身份、原始UID/日期或源路径。目录类型错误、权限、文件缺失及空间不足映射到安全中文处理建议，界面保留技术码。日志目录也不可写时记录失败不再抛出新异常，不得将失败任务改为成功。实际验证范围、发现及余项只记HANDOFF。
